# 產品感總覽

## 一句話

產品感不是會提需求，而是能判斷：什麼值得做、該怎麼做、做到什麼程度，以及做完後對使用者和業務是否真的有價值。

## 產品感是什麼

產品感是一種綜合判斷力，核心不是「想功能」，而是把使用者、商業目標、工程成本、體驗細節與驗證方式放在一起看。

它通常包含四個判斷：

| 判斷 | 要回答的問題 |
|---|---|
| 該不該做 | 這是真需求、重要問題，還是單一抱怨？ |
| 先做什麼 | 現在最值得投入的是哪一件事？ |
| 做到什麼程度 | MVP、80% 場景、完整方案，哪個版本最剛好？ |
| 怎麼做才舒服 | 使用者是否知道發生什麼、下一步做什麼，並感到安心？ |

## 為什麼 AI 時代更需要產品感

AI 讓寫程式、產圖、產文件和做原型的成本下降。團隊能更快做出很多東西，但這也放大了另一個問題：做得快，不代表做得對。

如果缺少產品感，團隊很容易出現：

- 做出很多低價值功能。
- 路線圖被零散需求塞滿。
- 使用者流程越做越複雜。
- 工程速度很快，但商業結果沒有等比例增加。
- 每個人都在忙，但沒有人能說清楚「為什麼這件事最值得做」。

AI 時代真正稀缺的能力，是在眾多可能性裡，判斷哪一件事最值得做。

## 產品感不是什麼

| 常見誤解 | 更準確的說法 |
|---|---|
| 產品感是 PM 的事 | 工程、設計、營運、客服都會影響產品結果 |
| 產品感等於靈感 | 它更接近基於情境、數據、成本與經驗的判斷 |
| 使用者說要就該做 | 要先判斷背後問題、影響範圍與替代方案 |
| MVP 就是隨便做 | MVP 是最小可驗證版本，不是最低品質版本 |
| 上線就是完成 | 上線只是開始，結果驗證才知道是否有效 |

## 團隊共同語言

討論需求時，盡量把對話從「要不要做功能」拉回「要解什麼問題」。

建議固定問五件事：

- 使用者現在遇到什麼問題？
- 這個問題的影響範圍和損失是什麼？
- 現在做的價值是否高於其他選項？
- 最小可驗證版本是什麼？
- 上線後看什麼指標或回饋來判斷有效？

## 好產品感的輸出

有產品感的人不一定會提出最多功能，但通常能產出更好的決策：

- 把模糊抱怨轉成清楚問題。
- 把大需求拆成可驗證版本。
- 把「想做」和「值得做」分開。
- 把工程成本納入產品決策。
- 把上線後的結果納入下一輪調整。
