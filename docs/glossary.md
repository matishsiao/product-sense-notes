# 詞彙表

## 產品感

能判斷什麼值得做、該先做什麼、做到什麼程度，以及做完後是否真的產生價值的能力。

## 真需求

背後有明確問題、使用情境、影響範圍和代價的需求。真需求不一定等於使用者口中的功能名稱。

## 假需求

看起來像需求，但可能只是單一抱怨、臨時 workaround、聲音大的意見，或未被驗證的解法。

## MVP

Minimum Viable Product，最小可驗證產品。重點是用最小成本驗證最重要假設，不是做一個品質很差的版本。

## Edge Case

少數或例外情境。產品感不是忽略 edge case，而是判斷它是否值得進入當前版本。

## Opportunity Cost

機會成本。做了 A，就代表同一段時間無法做 B。排優先級時要比較不同選項的價值。

## Success Metric

成功指標。用來判斷需求上線後是否有效，例如轉換率、完成率、留存、收入、錯誤率、客服量、操作時間。

## Leading Indicator

領先指標。比最終業務結果更早出現的信號，例如點擊率、完成率、啟用率、核心流程使用率。

## Lagging Indicator

落後指標。較晚反映的結果，例如收入、留存、流失率、長期活躍。

## Product Debt

產品債。過去為了速度或局部需求做出的體驗、流程或規則妥協，長期造成使用者困惑或團隊維護困難。

## Technical Debt

技術債。為了短期交付接受的技術妥協，未來會提高修改、測試、維護或擴充成本。

## Scope

需求範圍。包含本版做什麼、不做什麼、支援哪些使用者與情境。

## Rollout

上線策略。可以是全量上線、灰度、白名單、分批、feature flag 或人工開通。
